# 电机驱动子系统说明文档 (Motor Driver Subsystem)

## 1. 概述
本文档详细描述了基于 ESP32-S3 和 DRV8833 驱动模块的小车电机控制系统。文档涵盖了硬件电气连接逻辑、DRV8833 控制策略、软件封装架构以及控制任务流程，旨在为后续的运动控制算法开发（如人工势场法 APF）提供底层驱动支持。

## 2. 硬件架构

### 2.1 底盘布局
*   **驱动形式**：4WD（四轮驱动），差速转向。
*   **电机安装**：同侧电机采用**对置安装**（物理朝向相反）。
    *   *注意*：由于物理安装方向相反，同侧两个电机在电气上必须**反向并联**（错位并联），以确保在相同控制信号下车轮向同一物理方向滚动。

### 2.2 驱动芯片：DRV8833
*   **供电电压**：支持 2.7V - 10.8V。
*   **输出电流**：单通道 1.5A RMS, 2A 峰值。
*   **控制模式**：支持 PH/EN (相位/使能) 和 IN/IN (双输入) 模式。本系统采用 **IN/IN + Fast Decay** 模式。

### 2.3 经实测的启动特性 (6-8.4V VM, 空载)
*   **低于 50% 占空比**: 电机处于堵转状态，绕组相当于纯电阻，电流近似线性上升。
*   **50%~72% 占空比**: 电压接近启动阈值，电机内部微颤但未转动，电流加速上升 (磁场/电流波动加剧)。
*   **~72% 占空比**: 电机克服静摩擦开始转动。转动瞬间反电动势 (Back EMF) 建立，电流由 ~0.3A **跳变回落**。
*   **75%→100% 占空比**: 两侧均稳定转动，电流平稳上升至约 0.45A (空载)。
*   **结论**: 本系统电机最低有效占空比约 **72%**，考虑到因为公差造成的阈值差异，实际控制中应将 PWM 下限设置在 **72%~80%** 以保证稳定启动

### 2.4 PWM 配置 (ESP32-S3 LEDC)
*   **当前默认**: `20kHz / 10-bit (0-1023) / clk_cfg=LEDC_USE_APB_CLK (80MHz)`。
*   **API**: `drv8833_set_speed(&h, left%, right%)` — 百分比制 `[-100, 100]`, 0 = 滑行停车。内部将 `[1%, 100%]` 线性映射到 `[MIN_DUTY (=75%×MAX), MAX]`。调用方无需关心底层分辨率。
*   **可切换为**: `40kHz / 8-bit (0-255)`，仅需修改 `drivers/drv8833/drv8833_config.h` 中的 `DRV8833_PWM_FREQ_HZ` 与 `DRV8833_PWM_RES_BITS`。
*   **速度模式陷阱**: ESP32-S3 **不支持** `LEDC_HIGH_SPEED_MODE` (仅原始 ESP32 支持)。必须使用 `LEDC_LOW_SPEED_MODE`，时钟源通过 `clk_cfg` 字段控制。
    *   用 `LEDC_USE_APB_CLK` 显式选择 80MHz APB 时钟，不要依赖 `LEDC_AUTO_CLK`（可能选中 RC_FAST 17.5MHz 导致频率不足）。

### 2.5 引脚分配 (ESP32-S3)

| 功能 | ESP32 GPIO | DRV8833 引脚 | 备注 |
| :--- | :--- | :--- | :--- |
| **左侧方向/速度 1** | GPIO 5 | AIN1 | 主控制端 (PWM) |
| **左侧方向/速度 2** | GPIO 6 | AIN2 | 辅控制端 (Level) |
| **右侧方向/速度 1** | GPIO 7 | BIN1 | 主控制端 (PWM) |
| **右侧方向/速度 2** | GPIO 15 | BIN2 | 辅控制端 (Level) |
| **休眠使能** | 3.3V | STBY | 接 3.3V 保持芯片使能, 接地则休眠 |
| **电机电源** | 外部电池 | VM | 动力电源 (建议 6-8.4V) |
| **公共地** | GND | GND | ESP32 与驱动模块共地 |

> **注意**: 当前引脚映射为临时飞线方案 (见 `apf_common.h`)。原始 PCB 设计使用 GPIO 11,12,13,14，因设计失误改为现用引脚。

## 3. 电气连接与逻辑映射

### 3.1 电机并联策略
为了解决“同侧对置”带来的物理方向差异，采用以下接线逻辑：

*   **左侧电机组 (Left Group)**：
    *   连接至驱动输出 **AO1, AO2**。
    *   **接线方式**：错位并联。
        *   `Motor_Left_Top(+)` 接 `Motor_Left_Bottom(-)` 接 `AO1`
        *   `Motor_Left_Top(-)` 接 `Motor_Left_Bottom(+)` 接 `AO2`
    *   *效果*：当 AO1=High, AO2=Low 时，两个电机电气上一正一反，但物理上车轮均向前转。

*   **右侧电机组 (Right Group)**：
    *   连接至驱动输出 **BO2, BO1** (注意引脚顺序交换)。
    *   **接线方式**：配合驱动输出的交换，同样采用错位并联逻辑，或直接根据实际测试调整相位。
    *   *目的*：确保 `BIN1=High, BIN2=Low` 时，右侧车轮物理上向前转。

### 3.2 控制逻辑真值表 (DRV8833)

| 输入状态 (xIN1, xIN2) | 输出状态 (xO1, xO2) | 功能模式 | 推荐应用场景 |
| :--- | :--- | :--- | :--- |
| **PWM**, 0 | PWM, L | **正转 (Fast Decay)** | 前进、加速 |
| 0, **PWM** | L, PWM | **反转 (Fast Decay)** | 后退 |
| 1, **PWM** | H, PWM | **正转 (Slow Decay)** | 缓速前进 (电流平滑) |
| **PWM**, 1 | PWM, H | **反转 (Slow Decay)** | 缓速后退 |
| 1, 1 | L, L | **制动 (Brake)** | 急停 |
| 0, 0 | Z, Z | **滑行 (Coast)** | 惯性停车 |

*注：本系统推荐采用 **Fast Decay (快速衰减)** 模式，即 `xIN2=0, xIN1=PWM` (正转) 或 `xIN1=0, xIN2=PWM` (反转)，以获得更快的电机响应速度，利于避障算法。*

## 4. 硬件排查流程 (仅用万用表 DC 档)

按顺序逐项检查，每项通过后再进入下一项。

### 4.0 环境准备

*   将 ESP32 刷入固件，确保 `drv8833_init()` 已被调用 (PWM 通道已配置)。
*   在排查期间，**将小车悬空或断开电机与驱动输出的连接**，防止意外转动。
*   如需主动发送 PWM，可临时在 `app_main()` 中 `drv8833_init()` 之后插入测试代码 (见 4.4)。

### 4.1 电源检查

| 测量点 | 万用表档位 | 预期值 | 异常排查 |
|---|---|---|---|
| VM ↔ GND | DC 20V | 电池电压 (6-8.4V) | 检查电池、电源线极性 |
| STBY ↔ GND | DC 20V | ~3.3V | 检查 3.3V 连接是否牢固，STBY 引脚有无虚焊 |
| ESP32 3.3V ↔ GND | DC 20V | ~3.3V | ESP32 是否正常供电 |

### 4.2 静态电平检查 (PWM 全开/全关)

利用 `drv8833_brake()` 和 `drv8833_coast()` 函数，它们直接将 IN 引脚置为持续 HIGH 或 LOW，无需 PWM：

1. 调用 `drv8833_brake(&h)` 后，测量 **AIN1, AIN2, BIN1, BIN2 ↔ GND**，均应为 **~3.3V**。
2. 调用 `drv8833_coast(&h)` 后，同样测量上述引脚，均应为 **~0V**。

若两轮测试都通过，说明 ESP32 GPIO → DRV8833 IN 引脚的信号通路正常。

若全为 0V 或全为高阻态：
*   检查 IN 引脚与 ESP32 GPIO 之间的接线。
*   确认 `drv8833_init()` 是否返回 `DRV8833_OK` (检查串口日志有无 "DRV8833 initialized")。

### 4.3 PWM 平均电压检查

万用表 DC 档测 PWM 信号时，会显示 **平均电压 = 占空比 × 3.3V**。

1. 临时调用 `drv8833_set_speed(&h, 80, 80)` (80% 正向满速)。
2. 测量：

| 引脚 | 预期 DC 电压 | 说明 |
| :--- | :--- | :--- |
| AIN1 (GPIO5) | ~2.64V | 80% PWM |
| AIN2 (GPIO6) | ~0V | 0% |
| BIN1 (GPIO7) | ~2.64V | 80% PWM |
| BIN2 (GPIO15) | ~0V | 0% |

3. 再调用 `drv8833_set_speed(&h, -80, -80)` (反向)，AIN1/BIN1 应变为 ~0V，AIN2/BIN2 应变为 ~2.64V。

若某引脚始终 0V 或始终 3.3V，检查对应 GPIO 是否被其他外设占用，或 LEDC 通道配置是否冲突。

### 4.4 最小化测试代码

在 `app_main()` 中 `drv8833_init()` 之后临时插入，跳过 APF/Task 链路直接驱动：

```c
static void motor_test_drive(void) {
    int pct;                          /* 0~100% */
    const int step_ms = 40;           /* 每级时长 */

    ESP_LOGI(TAG, "=== Threshold Test: 0→100%%, step=%dms, 20kHz 10-bit ===", step_ms);

    while (1) {
        for (pct = 0; pct <= 100; pct++) {
            drv8833_set_speed(&g_motor, (int8_t)pct, (int8_t)pct);
            if (pct % 10 == 0) {
                ESP_LOGI(TAG, "duty: %d%%", pct);
            }
            vTaskDelay(pdMS_TO_TICKS(step_ms));
        }
        ESP_LOGI(TAG, "--- Coast 1s ---");
        drv8833_coast(&g_motor);
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

### 4.5 电机本体检查

用电池 (如 3.7V 锂电池或 2 节 AA) 直接触碰电机两端：
*   电机应转动。若不转，电机损坏。
*   转动时电流是否异常大 (手摸驱动芯片是否烫手)。

### 4.6 驱动输出端检查 (接上电机后)

| 测量点 | 万用表档位 | 预期 |
|---|---|---|
| AO1 ↔ AO2 | DC 20V | 前进时 AO1 > AO2，平均电压差与占空比成正比 |
| BO1 ↔ BO2 | DC 20V | 同上 |

若 IN 端信号正常但输出端无电压差，驱动芯片可能已损坏 (过流烧毁或进入保护锁死)。断电冷却后重新上电再试。

## 5. 常规注意事项

1.  **相序测试 (Phase Check)**:
    *   上电前确保小车悬空。
    *   发送"前进"指令，观察四个车轮是否均向前滚动。
    *   如果某侧车轮反转，**不要修改代码**，请检查该侧电机的"错位并联"接线是否正确，或者交换该侧驱动输出线 (AO1/AO2)。

2.  **电流保护**:
    *   DRV8833 发热严重时会自动关断 (nFAULT 拉低)。
    *   本系统电机有效占空比下限约 70%，低于此值的 PWM 输出仅为绕组发热，产生堵转电流无实际驱动力。实际控制时应将 PWM 下限设置在 70%~80%。

3.  **占空比下限 (Deadband)**:
    *   见 2.3 节启动特性。低于 72% 的 PWM 指令应在上层算法中映射为零驱动力，避免无效发热。

4.  **死区时间**:
    *   在电机换向 (正转 -> 反转) 时，建议插入 10ms-50ms 的"制动"或"滑行"死区，防止电流冲击损坏驱动芯片。

5.  **电源去耦**:
    *   电机启动瞬间电压跌落可能导致 ESP32 重启。务必在 DRV8833 的 VM 和 GND 之间并联大容量电容 (如 470uF 电解电容 + 0.1uF 陶瓷电容)。

## 6. 软件架构整合

底层驱动为 `drivers/drv8833/` **adapt-drv 分层驱动库**（核心层 + `internal/` 底盘算法 + `port/` LEDC 移植层）。
控制任务 `tasks/motor_task.c` 只做薄封装：队列接收 → `drv8833_set_velocity()` → 周期 `drv8833_update()`。

### 6.1 一阶低通滤波 (LPF)

`q_cart` (笛卡尔合力向量) 在 drv8833 核心层内经一阶低通滤波，再送入底盘算法：

```
y[n] = α·target + (1-α)·y[n-1]
α = DRV8833_LPF_ALPHA = 0.90（drv8833_config.h，可编译期/运行期启停）
dt = 1000/MOTOR_FREQ_HZ = 125ms (8Hz)
```

| α 值 | 阶跃响应 |
|---|---|
| 0.90 (默认) | 快速收敛，抑制单帧跳变 |
| 1.00 | 无平滑（直通） |
| 0.50 | 大幅平滑 |

### 6.2 四轮差速映射 (internal/drv8833_chassis_diff4wd.c)

当前启用的底盘算法：**dx/dy 直接差速映射**，无角度分解。转向比例始终可预测，调参直观：

```
dx_u = dx / vel_max_mm           // 归一化到 [-1, 1]
dy_u = dy / vel_max_mm
scale = 1 - |dy_u| × DX_COUPLING // |dy| 越大前进越慢，避免转向过快致雷达畸变
propulsion = dx_u × scale
steering   = dy_u × STEER_GAIN
if propulsion < DEAD_ZONE: propulsion ×= REV_GAIN   // 后退减速
left  = propulsion - steering
right = propulsion + steering
if left×right < 0: left/right ×= SPIN_GAIN          // 自旋时削弱转速
→ 比例限幅(仅在超限时) → drv8833_set_speed(left%, right%)
```

设计目标：无角度分解的非线性跳跃，转向率可预测；
原地转向转速由 dy 幅值自然缩放（近障碍物时力小→转速慢，开阔空间力大→转速快）。

### 6.3 底盘扩展

`DRV8833_CHASSIS_SELECT` 宏选择底盘算法。当前实现 `DIFF_4WD`；
2WD / 麦克纳姆轮 / 履带为预留接口（`internal/drv8833_chassis.c` 注册表分发，
未实现类型 `init()`/`update()` 返回 `DRV8833_ERR_NOT_SUPPORTED`）。

### 6.4 旧算法 (已弃用, 代码已删除)

原 `motor_classify()` 将合力向量分为 5 种模式 (M_DEAD/M_SPIN/M_SPIN_L/M_FWD/M_REV), 每个模式独立计算 PWM。
早期还尝试过幅值-角度分解 (`atan2` 求角 + `cos/sin` 映射)。均已被 6.2 的直接差速映射替代。
